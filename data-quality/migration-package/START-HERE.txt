────────────────────────────────────────────────────────
3) PuTTY  →  migration-package/03-putty/
   (same steps are also on the server as SERVER-SETUP.txt)
────────────────────────────────────────────────────────
Requirements: Node.js 22.x  |  MariaDB reachable on port 3306

  cd /var/www/Data_Quality_Tool
  cp .env.production.example .env.local
  nano .env.local          # set DB_HOST, DB_USER, DB_PASSWORD; COOKIE_SECURE=false for HTTP
  chmod -R u+rwX data
  npm install
  cd capacity && npm install && cd ..
  npm run build
  npm run start            # test only — stops when you close PuTTY

Keep it running after logout (recommended):
  sudo npm install -g pm2
  pm2 start npm --name data-quality-tool -- start
  pm2 save
  pm2 startup              # run the command it prints

Or:  bash server-commands.sh /var/www/Data_Quality_Tool

Behind Nginx? Install 03-putty/nginx-data-quality-tool.conf instead of writing
your own, and keep PORT in .env.local equal to proxy_pass in that file.
Getting 502 Bad Gateway? README-PuTTY.txt section 10 tells you which of the
three causes you have in about a minute.

Details: 03-putty/README-PuTTY.txt

────────────────────────────────────────────────────────
Redeploying later (updated files)
────────────────────────────────────────────────────────
After uploading new files with WinSCP:

  cd /var/www/Data_Quality_Tool
  npm install
  cd capacity && npm install && cd ..
  rm -rf .next
  npm run build
  pm2 restart data-quality-tool     # or npm run start

Then hard-refresh the browser once (Ctrl+Shift+R). Each build
regenerates public/capacity with new chunk names, so a stale
cached page can otherwise ask for files that no longer exist.
